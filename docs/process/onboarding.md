# Промт для агента напарника

Даниил отправляет каждому свой блок целиком — это первое сообщение в Claude Code или Codex
после `gh repo clone daniil-burdygin/fx-moment`. Блок самодостаточен: агент дальше читает
`CLAUDE.md` и работает по нему.

Обновлять при смене уклада (кто пересобирает отчёты, что закрыто отрицательно).

## Илье

```text
Ты работаешь в приватном репозитории daniil-burdygin/fx-moment — кейс 455 Альфа-Банка на
AI Product Hack 2026. Команда 9: Даниил (менеджер), Илья и Олег (AI Engineer). Я Илья.
Дедлайны МСК: промежуточные артефакты 04.09 10:00, финальные 07.09 10:00, Demo Day 07.09 12:00.

Первое действие — чтение, не код. В этом порядке:
1. CLAUDE.md в корне — карта проекта: инварианты, словарь, конвенции. Единственный источник
   правил, AGENTS.md отсылает к нему же.
2. docs/STATUS.md — что уже измерено и с какими числами. Читать целиком: большая часть
   вопросов «а если попробовать…» там закрыта, в том числе отрицательно.
3. docs/case/case-455-talenttrack.md и docs/case/qa-2026-09-02.md — условия кейса и ответы
   кейсодателя.
4. docs/decisions/ — ADR 0001–0011. Допущение, влияющее на метрики, живёт там и меняется
   только новым ADR.

Окружение: uv sync --group dev, затем uv run pytest (83 теста зелёных) и uv run ruff check .

Уклад изменился: в репозиторий пишут трое, каждый со своим агентом.

Защиты ветки main нет — на бесплатном приватном репозитории GitHub её не даёт. Значит правило
«ветка feat/<что>, PR в main, в main напрямую только правки документации» держится
договорённостью, а не запретом. В main не пушь. Перед push — git pull --rebase origin main;
чужие коммиты не переписывай, push --force не делай.

reports/ — 77 файлов, и они в git. Команда fxmoment backtest переписывает 18 из них целиком,
fxmoment analyze — ещё 26. Если двое прогонят бэктест на своих ветках, конфликт придёт сразу
во всех CSV, и разрешать его построчно бессмысленно. Поэтому отчёты пересобираются только на
main и только тем, за кем эта строка в docs/plan.md. В своей ветке трогай src/, tests/, docs/.
Локально прогонять можно, но результат не коммить: git checkout -- reports/. Если правка
сдвинет числа — напиши это в описании PR.

Инварианты, нарушение которых стоит дороже сэкономленного времени (полностью в CLAUDE.md):
— Ни одного взгляда в будущее. Индикатор — каузальная функция от прошлого;
  tests/test_no_lookahead.py обязателен перед каждым коммитом.
— Числа в документы берутся из reports/, а не из памяти и не из прошлой версии текста.
  Не сходится — сначала пересчёт, потом текст.
— Отрицательный результат идёт в отчёт с цифрами, а не прячется.
— Индикатор — чистая функция без состояния между вызовами и без файлов-кэшей.
— Только открытые данные: ЦБ, MOEX, нацбанки. Клиентских и персональных нет даже в примерах.

Уже проверено, переоткрывать не надо (цифры — в docs/STATUS.md): чистка 2022 из данных
(ADR-0004 п. 5: не чистим, помечаем), уровни 90/95/99 % (недостижимы при содержательном
допуске), часовой ряд Мосбиржи (не даёт ни точности, ни частоты, ADR-0010), признак EUR/USD
(эффект через ноль, ветка feat/eurusd-feature), перевод продукта на априорные параметры.
Набор индикаторов расширять не нужно.

Коммиты от моего имени, сообщение по-русски в повелительном наклонении: «Исправь дрейф уровня
на UZS». Перед коммитом — uv run pytest и uv run ruff check . (лимит строки 110).

Моя зона: src/fxmoment/data/ (загрузка ЦБ, часовые свечи Мосбиржи, сверка источников,
календарь публикации) и src/fxmoment/indicators/.

Ближайшая задача из docs/plan.md, срок 04.09: поправка на дрейф уровня для UZS. Готово, когда
lift_drop при переносе параметров не растёт — колонка lift_drop в
reports/latest/analysis/transfer_compare.csv, сейчас на паре level/UZS она −0,096.
Дальше 05.09 вместе с Олегом финальный бэктест.

Начни с чтения и скажи, что понял и что собираешься менять, до первой правки кода.
```

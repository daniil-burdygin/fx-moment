# Замер: уровень с вычтенным дрейфом локальной ноги (`level_drift`, вариант `reports/level-drift/`)

Не ADR: решение не принято. Это замер по пункту 2 решения 💬 03.09 вечера («разложить коридор на
общий фактор и локальную ногу»), чтобы решать по числам.

**Что добавлено.** Курс RUB→X = USD/RUB × (X/USD)⁻¹: общий фактор — доллар к рублю, локальная нога
`local = rate / usd` — стоимость местной валюты в долларах. У UZS локальная нога устойчиво дешевеет,
и «один из низких за полгода» у такого ряда — почти любой день: новый минимум ставит не выбор
момента, а сам дрейф. Индикатор `level_drift` (`src/fxmoment/indicators/level_drift.py`) считает
процентиль уровня среди значений окна, приведённых к сегодняшнему дрейфу: rate_s · exp(d_t · (t − s)),
где d_t — средний дневной лог-шаг локальной ноги за скользящие 250 дней публикации, только прошлое.
При нулевом дрейфе это ровно `level`; на ряде с одним дрейфом и шумом процентиль держится около
половины, а у `level` — около нуля (`tests/test_variant_indicators.py`). Сетка та же, что у `level`
(окно 60/120/250, процентиль 0,05–0,30, остановка 0/3, перезаряд 3/5); окно дрейфа одно, год, чтобы
сравнение с `level` было сравнением приведения, а не ещё одной степени свободы. Дрейф — отдельный
факт (`drift_pct_year`) и текст пуша «курс сума к доллару за год снизился на …» (через `check-texts`).
Индикатор стоит рядом с `level`, не вместо: `backtest --with-level-drift --out level-drift`, сравнение
`compare-runs --variant level-drift --pair level_drift=level`.

**Где именно помогает и где ломает.** UZS: 2024-H1, 2024-H2 и 2025-H1 lift 1,95 / 1,25 / 1,30 против

ровно, а ступенями, и годовой дрейф отстаёт от шага: приведённое окно считает ступень «низким
уровнем». От 64 до 86 % событий `level_drift` лежат в трёх днях от события `level` — новых моментов
он добавляет немного.

**Что вариант делает с потоком** (`stream_compare.csv`, `decisions.csv`). Политика пропускает
`level_drift` в 137 событиях из 682, глушит в 231 (KZT и окна с lift < 1), прореживает 107; `level`
при этом отправлен 193 → 155 раз, прорежен 76 → 122. Пушей 735 → 787 (KGS +17, TJS +16, UZS +14,
AMD +4, KZT +1). `BUY_NOW`: 645 → 706 событий, lift 1,041 → 1,048, выгода +34,3 → +33,4 бп —
интервалы через ноль в обоих блоках. Без базы то же. Доля попаданий 0,532 → 0,535, выгода вперёд
+28,9 → +28,1 бп. Поток громче на 52 пуша без прибавки точности.

**Как читать.** Поправка на дрейф работает там, где дрейф ровный (UZS, отчасти KGS), и ломается там,
где локальная нога дешевеет ступенями (KZT). Правило устойчивости ADR-0004 требует эффекта
одновременно на нескольких коридорах — его нет: один интервал выше нуля, два ниже, остальные через
ноль.

**Открытый вопрос к Даниилу.** Брать ли `level_drift` в стек. 🧩 Предложение агента: нет — поток
громче без точности, параметры переносятся хуже, чем у `level`, а выигрыш на UZS не подтверждён
интервалом. Дрейф оставить фактом для экрана и текста (там он объясним за секунду) и приложением к
отчёту с разбором по коридорам. Поправку Ильи на дрейф UZS (план, пт 04.09), если она сформулирована
иначе, сверять этой же парой `compare-runs --pair`, а не заводить второй вариант.

**Воспроизвести:**

```bash
uv run fxmoment backtest --with-level-drift --out level-drift
uv run fxmoment compare-runs --variant level-drift --pair level_drift=level
```

Коннектор ISS готов, сверка «биржа против фиксинга ЦБ» сделана — и первой же проверкой сузила задачу. Моментум поднимается с 0,89–1,04 до 1,05–1,12, но интервалы разницы через ноль на всех пяти коридорах. Уровень почти не двигается (0,996–1,27 против 1,01–1,18) — он устойчив к выбору базы; на AMD теряет (интервал −48…−1). Разворот на месячной базе, наоборот, уходит ниже единицы на четырёх коридорах из пяти (0,92–1,01 против 0,96–1,21) — он выигрывал у полугодовой базы за счёт выбора месяца. Сезонность почти не двигается.

🧩 Что из этого следует. Выбор базы двигает lift на величину до 0,28 — больше, чем большинство измеряемых нами эффектов. Это само по себе результат, и он идёт в отчёт: сравнивать надо не только индикаторы, но и то, с чем их сравнивают. Головной остаётся оконная база — она консервативнее и отвечает на вопрос «выиграл ли клиент за полугодие»; месячная стоит рядом и отвечает на вопрос «попали ли мы в удачный день внутри месяца», то есть на тот, который клиент решает на самом деле. Записано как ADR-0011, ждёт подтверждения Даниила. Там же неприятное следствие: ранг индикаторов и правило отключения считают lift на оконной базе, и за 11 окон провал к тренду отключён в 309 случаях из 496 — политика глушит на 62 % событий тот индикатор, который на клиентской базе работает везде. До сдачи не трогаем: правка ранга перестраивает весь поток и все отчёты. Механизм сдвига понятен: события провала к тренду кучкуются в месяцах, когда рубль слабеет, и оконная база штрафовала их за выбор месяца, а не за выбор дня.

**Сезонность и налоговый период** (`analysis/day_of_month.csv`, `day_of_month.png`). Гипотеза: экспортёры продают валюту под налоги к 28-му, рубль к концу месяца крепче, отправителю дешевле. Направление подтверждается на всех пяти коридорах: в окне 20–28 числа курс ниже среднего за свой месяц на 8–44 бп, а разница с остальными днями месяца — 12–63 бп. После снятия линейного тренда внутри месяца разница сжимается до 2,7–17,0 бп, но знак сохраняют все пять. Форма месяца читается: числа 6–14 дороже своей линии, 15–25 дешевле с провалом на 25-м, а 26–28 — резкий возврат вверх.

🧩 Что из этого следует. Механизм согласуется с данными, но не доказан. Коридоры скоррелированы с USD/RUB на 0,83–0,97, поэтому пять коридоров — почти одно наблюдение; интервал не пересекает ноль лишь у 11 клеток «коридор × число» из 155 при ожидаемых случайно восьми. Провал приходится на 15–25, а не на априорное окно 20–28, и переопределять окно под найденный провал мы не будем — это ровно та селекция, которую разбираем в других местах отчёта. Индикатор сезонности стреляет с 20–24-го числа, то есть попадает в провал, и это уже причинная проверка: он смотрит только на прошлые годы.

**Интервалы блоками по окну** (`analysis/calibration_vs_fixed.csv`, столбцы `*_by_window`; 03.09 вечер). Коридоры скоррелированы с USD/RUB на 0,83–0,97, а блок «коридор × окно» считает пять почти одинаковых коридоров пятью наблюдениями — интервал выходит уже, чем он есть. С блоком по окну (11 блоков) итоговая разница калибровки с априорными точками — те же 0,05, но интервал [−0,03; +0,14] содержит ноль; у разворота [−0,06; +0,47] тоже. Уровень ([+0,05; +0,25]), сезонность ([+0,05; +0,53]) и провал к тренду ([−0,34; −0,01]) вердикт сохраняют. Все парные сравнения отчёта теперь показывают оба интервала, и там, где они расходятся, верить надо более широкому.

**Календарное правило как база** (`analysis/calendar_rule.csv`, `calendar_vs_stack.csv`; 03.09 вечер). Правило без индикаторов, параметров и модели — «первый день публикации с 25-го числа». На 11 окнах оно даёт pooled lift 1,12 (по коридорам 1,06–1,18) и +71 бп сверх случайного дня (+60…+83) при 0,23 в неделю; «первый день с 20-го» — 1,08 и +31 бп. Стек это правило не обгоняет. Уровень (1,11, +44 бп) и обучаемый (1,16, +37 бп) от него не отличимы. Интервалы разницы содержат ноль и по lift, и по выгоде при обоих блоках. Поток хуже. `BUY_NOW` итогового потока (1,04, +34 бп) по выгоде уступает правилу «25-е» 36 бп при интервале [−55; −18] по парам и [−64; −11] по окнам — целиком ниже нуля в обоих. Провал к тренду хуже на 102 бп по парам ([−159; −43]), по окнам через ноль.

🧩 Что из этого следует. Календарь — не конкурент стека, а его нижний слой: он объясним за секунду, не требует ни данных, ни модели и уже даёт большую часть выгоды, которую мы меряем. Индикаторы обязаны доказывать прибавку над ним, а не над случайным днём, и сейчас доказать не могут. Для экрана перевода это готовый факт («в 2021–2026 первый день публикации с 25-го был не хуже среднего следующих 20 дней в 56 % случаев против 50 % у случайного дня»), для жюри — честная точка отсчёта. Окно правила задано до замера: провал формы месяца приходится на 15–25 числа, и переопределять правило под него мы не стали.

**Выживаемость сигнала до исполнения** (`analysis/execution_survival.csv`; 03.09 вечер). Пуш уходит вечером T, клиент переводит на T+1 по курсу приложения. Гейт уровня (`rank120 ≤ 0,2`), истинный вечером T, остаётся истинным по курсу T+1 у 87–98 % пушей `BUY_NOW` итогового потока (pooled 93 %), собственный факт индикатора — у 89–93 % (91 %). Спред: постоянная часть расхождения приложения с фиксингом на выбор дня не влияет и снята, считается отклонение сегодняшнего расхождения от среднего. На паре CNY за 2021–2026 (единственной, где биржа и фиксинг мерят один курс) среднее расхождение +14 бп, девятый дециль отклонения +74 бп. В ожидании по этому распределению выгода пуша не меняется (+29 → +30 бп pooled, попадание 0,53 → 0,55), но в девятом дециле уходит в минус: −45 бп по всем коридорам, от −37 до −90 на четырёх коридорах из пяти, AMD +5. На собственных парах KZT и AMD разброс втрое больше (девятый дециль +222…+247 бп), там выгода при неудачном спреде −140…−215 бп; это верхняя граница — эти пары с кросс-курсом ЦБ связаны слабо.

🧩 Что из этого следует. Девять пушей из десяти утром ещё верны, и это число для экрана: механика «момент изменился» нужна для десятого пуша и для хвоста спреда, а не для каждого. Хвост в десять процентов дней съедает всю выгоду сигнала — довод за механику A из `star-task.md` (честная дельта на экране), а не за фиксацию курса.

**Разворот как факт, не прогноз** (`analysis/reversal_regret.csv`; 03.09 вечер). Сценарий «окно закрывается» мерился как прогноз «через 20 дней курс не ниже» и был монеткой. Как факт для того, кто получил `BUY_NOW` и не перевёл, он выглядит иначе. По событиям индикаторов у каждого разворота есть `BUY_NOW` за 1–2 дня до него, и курс к развороту уже вырос. Медиана сожаления +41…+62 бп по коридорам (+54 pooled), среднее +81…+124 бп с интервалами целиком выше нуля на всех пяти; больше рабочего допуска 25 бп в 54–68 % пар. По пушам потока (81 пара из 90 разворотов, `BUY_NOW` в среднем за 5 дней до) медиана +33 бп, среднее +99 бп [+16; +184]. Прогнозные прочтения остаются у базы: через 20 дней lift 0,96–1,21 (pooled 1,08), до конца календарного месяца 0,97–1,31 (1,07).

🧩 Что из этого следует. Роль сценария — не «курс будет выше», а «после подсказки прошло пять дней, курс уже выше на столько-то»: факт о прошлом, честный для клиента, который не перевёл, и не требующий прогноза. Текст пуша не меняется — он и так называет только прошлое; роль сценария переписана в `concept.md`.

**Окно клиента: решение клиента, а не индикатора** (`analysis/client_window.csv`, `client_window_windows.csv`; 04.09 ночь, строка Ш5). Клиент переводит раз в месяц и выбирает один день в своём окне; стратегии сравниваются на одном и том же окне, метрика — курс стратегии против курса привычки в бп, интервалы — блочный бутстреп по месяцам, пять коридоров месяца в одном блоке. Два семейства портретов. «Ожидание»: деньги пришли 5, 10, 15, 20 или 25-го, срок через 5, 10 или 15 дней публикации, привычка — перевести сразу, без пуша клиент ждёт до срока; 4915 окон за 66 месяцев. «Ускорение»: деньги есть с 5-го или 10-го, привычный день перевода 15, 20 или 25-е. Пуш может только приблизить перевод; без пуша клиент переводит как обычно. Окон 1980.

В семействе «ожидание» оракул забирает +232 бп к привычке [+170; +317] — верхняя граница боли на месячном окне, 695 ₽ с перевода 30 000 ₽. Календарь «первый день с 25-го, иначе срок» даёт +55 бп [+1; +114] и 24 % выигрыша оракула. Пуш потока «первый пуш в окне, иначе срок» — +11 бп [−49; +82] и 4 % оракула, то есть 33 ₽ с перевода. Раскладка: в окна с пушем (53 %) клиент выиграл +85 бп [+35; +151], 254 ₽ с перевода, а в окнах без пуша ожидание до срока проиграло. «Пуш, иначе календарь» — +39 бп [−8; +100]. Факт экрана «ниже, чем в 80 % дней за полгода» сдвигает перевод в 13 % окон, в них даёт +266 бп, суммарно +3 бп. Доля окон, где стратегия хуже привычки больше чем на 25 бп: у пуша 35 %, у календаря 31 %, у ожидания до срока 46 %. По портретам картина двоится. Там, где деньги приходят 5–10-го и ждать можно 10–15 дней, само ожидание даёт +63…+121 бп, а пуш, пришедший раньше срока, часть выигрыша отдаёт (+21…+85). Там, где деньги приходят 20–25-го, ждать вредно (−16…−86), и пуш тоже (−53…−74 у 25-го).

В семействе «ускорение» пуш вредит: −38 бп к привычке [−80; −0,3]; в окнах с пушем (57 %) −66 бп [−131; −3]; факт экрана −54 бп [−105; −12]. Причина — форма месяца: курс к 20–25-му числу ниже, чем в его начале, привычный поздний день уже близок к минимуму месяца, а пуш зовёт перевести раньше него. Знак одинаков на всех пяти коридорах, целиком ниже нуля интервал у KGS и UZS.

🧩 Что из этого следует. Ценность пуша есть у клиента, который переводит сразу по приходу денег в первой половине месяца, и только когда пуш пришёл: +85 бп с интервалом выше нуля. Клиента с привычкой переводить 20–25-го дёргать раньше нельзя — это измеренный вред, и сегмент пилота задаётся этим: клиенты, чьи переводы ложатся в первую половину месяца. Форма месяца — главный рычаг в клиентской рамке, и место ей на экране всегда («ваш обычный день, 25-е, в 2021–2026 был одним из дешёвых в месяце»), а не в пуше. Формула потенциала кейсодателя получает измеримые множители: доля сдвинутых окон 53 % при +85 бп в сдвинутом окне.

Главный вывод для концепции: на 1–5 днях ряд ЦБ почти непредсказуем, сигнал есть на горизонте месяца — это горизонт клиента, переводящего к зарплате. Быстрые индикаторы не дают ничего; календарное правило без индикаторов даёт большую часть выгоды, и стек обязан доказывать прибавку над ним; «окно закрывается» — факт о сожалении, а не прогноз. Пуш редкий (≈ 2 в месяц на коридор), факт о курсе на экране перевода — всегда. Ранг на месячной базе и длинная история ранга поток не улучшают — замерено вариантными прогонами.

Разбор — `docs/decisions/evening-gate-experiment.md`, команды `fetch-forts` и `evening-gate`.

**Ш14 закрыта отрицательным результатом.** Операции Минфина по бюджетному правилу собраны из первоисточников за 2018-06…2026-09 (`data/minfin_fx_operations.csv`, 101 строка, источники и дыры — в `data/minfin_fx_operations.md`) и разложены по дням каузально: в режим дня T входят только объявления с `announce_date ≤ T`, это проверяет `tests/test_minfin.py`. Разрез `analysis/minfin_regime.csv` — крючок в `analyze`. Режим двигает базу, а не сигнал: в дни продажи валюты случайный день попадает в «курс не хуже 20 дней» с вероятностью 0,69 против 0,51 в дни покупки, а lift уровня и потока держится около единицы во всех трёх режимах. Интервалы разниц `продажа − покупка` и `пауза − покупка` содержат ноль по обеим метрикам. Признак обучаемому не добавлен; как подключить, если решение будет обратным, описано в `docs/decisions/minfin-experiment.md`.

**Ш8, один сигнал по рублю** (вариант `reports/ruble-signal/`, сравнение в `vs_latest/`; `backtest --signal-source USD --out ruble-signal`). Индикаторы считаются по USD/RUB, попадания и база — по каждому из пяти коридоров; сигнал один, даты и параметры на коридорах совпадают, 673 события на коридор, 66 калибровок вместо 330. Основание: дневные лог-доходности коридоров скоррелированы с рублём на 0,822–0,978, знак шага совпадает у 81–96 % дней. Суммарный lift не сдвинулся (1,041 → 1,041 при интервале [−0,04; +0,04]). По индикаторам разнонаправленно: уровень 1,107 → 1,190, сезонность 1,031 → 1,118, разворот 1,077 → 1,001, моментум 0,980 → 0,941 (по окнам интервал целиком ниже нуля), обучаемый 1,156 → 1,121. Целиком в стороне от нуля в обоих блоках пять клеток «индикатор × коридор» из тридцати: за общий сигнал — уровень на KGS (+0,195) и сезонность на KZT (+0,214), против — обучаемый на AMD (−0,336), разворот на UZS (−0,220) и моментум на KZT (−0,102). Поток: 735 → 714 пушей, `BUY_NOW` lift 1,041 → 1,091, выгода +34,3 → +44,2 бп — интервалы через ноль; без базы доля попаданий 0,522 → 0,552. Перенос параметров между коридорами у общего сигнала тождественно нулевой — вопрос снят определением, а не замером. 🧩 Пять коридоров подтверждением друг для друга не служат, и замер показывает это числом: сигнал, сведённый к одному, даёт ту же точность при впятеро меньшей стоимости калибровки — готовый ответ на вопрос кейсодателя из `qa-2026-09-02.md`. В стек до сдачи не переносить: головные интервалы содержат ноль, а сдвинулись бы числа всех документов. Оговорка: обучаемый на общем ряду теряет признаки локальной ноги, его строка недооценена. Разбор — `docs/decisions/ruble-signal-experiment.md`.

## Как воспроизвести

```bash
uv sync --group dev && uv run pytest && uv run fxmoment backtest
uv run fxmoment backtest --fixed-params   # до analyze: сравнение калибровки читает его матрицу
uv run fxmoment analyze                   # в том числе праздники, окно клиента, режим Минфина
uv run fxmoment evening-gate              # вечерний гейт по фьючерсам, отдельной таблицей
uv run fxmoment signals --as-of 2026-06-22 --decide --texts
uv run fxmoment timemachine               # prototype/timemachine.html из reports/latest
uv run fxmoment compare-sources && uv run fxmoment intraday
uv run fxmoment backtest --rank-base month --out rank-month && uv run fxmoment compare-runs --variant rank-month
uv run fxmoment backtest --first-test 2019-01-01 --out from2019 && uv run fxmoment compare-runs --variant from2019
uv run fxmoment backtest --ml pooled --out ml-pooled && uv run fxmoment compare-runs --variant ml-pooled --pair ml_localmin=ml_localmin
uv run fxmoment backtest --with-level-drift --out level-drift && uv run fxmoment compare-runs --variant level-drift --pair level_drift=level
uv run fxmoment backtest --ml-features eurusd --out ml-eurusd && uv run fxmoment compare-runs --variant ml-eurusd --pair ml_localmin=ml_localmin
uv run fxmoment backtest --ml-features timesfm --out ml-timesfm && uv run fxmoment compare-runs --variant ml-timesfm --pair ml_localmin=ml_localmin
uv run fxmoment backtest --ml pooled --ml-features eurusd --out ml-pooled-eurusd && uv run fxmoment compare-runs --variant ml-pooled-eurusd --pair ml_localmin=ml_localmin
uv run fxmoment backtest --signal-source USD --out ruble-signal
uv run fxmoment compare-runs --variant ruble-signal \
  --pair level=level --pair ml_localmin=ml_localmin --pair dip_vs_trend=dip_vs_trend \
  --pair momentum=momentum --pair reversal=reversal --pair seasonality=seasonality
uv run fxmoment backtest --freq-band 0.1 0.3 --out precision
uv run fxmoment compare-runs --variant precision \
  --pair level=level --pair ml_localmin=ml_localmin --pair dip_vs_trend=dip_vs_trend \
  --pair reversal=reversal --pair momentum=momentum --pair seasonality=seasonality
```

⚠️ `fetch`, `fetch-moex`, `fetch-forts` и `fetch-forecast` в этот круг не входят: снимки лежат
в `data/raw/` и `data/derived/`, а свежая выгрузка сдвинет данные и сломает побайтовую сверку.

Порядок важен: `analyze` читает `reports/latest` и `reports/fixed`, `intraday` — матрицу
`reports/latest`, поэтому все пять отчётов собираются подряд на одном коммите. Провенанс каждого без суффикса `-dirty` —
проверка того, что так и вышло. Вариантные прогоны — после них. Каждый пишет в свой каталог и
`reports/latest` не трогает, а `compare-runs` читает оба. Пары с одинаковыми именами индикаторов
нужны ради разбивки по коридорам: без них `matrix_compare.csv` даёт сравнение только по всем сразу.
Прогон `--ml-features` без флага переписывает `reports/latest` побайтово тем же — признаки
включаются только флагом.
